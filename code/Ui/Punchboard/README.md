# Punchboard UI components

Generic, game-agnostic Razor components in the "Punchboard Deluxe" cardboard board-game style. They know nothing about `CityGame` or `MatchState`: every component takes plain parameters and raises plain callbacks. A game screen is expected to **map its own state onto these components**.

The design rules, tokens and asset guidance live in the `punchboard-design-system` agent skill (`.claude/skills/` and `.agents/skills/`). Read that before changing a look.

Namespace: `CitySim.Punchboard`. In a Razor file add `@using CitySim.Punchboard`.

## Components

| Component | Purpose | Main parameters |
|---|---|---|
| `PbPanel` | Chipboard panel with printed frame | `Title`, `Kind` (Standard, Raised, Tooltip), `Corner`, `<ChildContent>` |
| `PbButton` | Press-out button | `Text`, `Icon`, `Kind`, `Size`, `Disabled`, `Toggled`, `Clicked` |
| `PbCard` | Playing card | `Title`, `Icon`, `Rarity`, `Tags`, `Text`, `Accent`, `HotKey`, `Selected`, `Disabled`, `Compact`, `Clicked` |
| `PbHand` | Fans its `PbCard` children, lifts hovered or selected | `FanStep`, `HoverLift`, `SelectedLift`, `<ChildContent>` |
| `PbTagPill` | Tag chip with icon | `Tag`, `Label` |
| `PbRarityMarker` | Shape plus colour rarity marker | `Rarity`, `ShowLabel` |
| `PbStat` | Die-cut number window (coins, points) | `Icon`, `Value`, `Label`, `Tone` |
| `PbSlot` | Recessed effect-tray slot with count badge | `Icon`, `Count`, `Empty`, `TooltipText`, `Inspected` |
| `PbMeter` | Recessed progress bar | `Value` (0-1), `Label`, `Text`, `Tone` |
| `PbToggle` | On/off switch | `Label`, `Value`, `ValueChanged` |
| `PbTabs` | Segmented tabs | `Items`, `Selected`, `SelectedChanged` |
| `PbDial` | Round timer dial | `Fill` (0-1), `Text`, `Alert` |
| `PbBanner` | Ribbon banner | `Caption`, `Title`, `Tone` |
| `PbTooltipCard` | Ready-made tooltip content | `Title`, `Text`, `Rarity`, `Tags`, `Live` |
| `PbRoundTrack` | Round pips | `Total`, `Current` |
| `PbMeeple` | Player marker | `Tint` |
| `PbModal` | Dialog on a scrim | `Open`, `Title`, `Dismissed`, `<ChildContent>`, `<Actions>` |
| `PbIcon` | Emoji, glyph or texture | `Icon` |
| `PbShowcase` | Live catalogue of everything above (a `PanelComponent`) | none |

Enums are in `PbTypes.cs` (`PbRarity`, `PbTag`, `PbTone`, `PbButtonKind`, `PbSize`, `PbPanelKind`). Helpers (easing, colour strings, glyphs) are in the static `Pb` class.

## Using them

```razor
@using CitySim.Punchboard

<PbPanel Title="Resources">
	<ChildContent>
		<PbStat Icon="🪙" Value=@coins.ToString() Tone=@(PbTone.Accent) Label="Coins" />
		<PbButton Text="Ready" Toggled=@ready Clicked=@(() => { ready = !ready; }) />
	</ChildContent>
</PbPanel>
```

Rules learned from the engine, keep to them:

1. **Nested content needs an explicit `<ChildContent>` element** (and named fragments such as `<Actions>`). Without it the Razor generator fails with "does not contain a definition for 'div'".
2. **Lambdas for callbacks must be block-bodied** (`() => { x++; }`), and generic callbacks need a cast: `(Action<bool>)(v => { ... })`.
3. **Components are controlled.** `PbToggle`, `PbTabs` and `PbCard` do not change their own value. Update the value in the parent from the callback.
4. **Never name a CSS class `tooltip`.** The engine has its own `.tooltip` style. Panel kinds use `pb-kind-*` classes.
5. **Sass maths is not evaluated** (`$a * 2` is rejected). Use precomputed tokens such as `$pb-radius-lg`.
6. **Conic gradient stops use `%` or `px`, not `deg`.**
7. **Components set `pointer-events: all`** where they are interactive, so they work inside a HUD whose root is `pointer-events: none`.
8. **Fonts:** `Lilita One` and `Nunito` are not in the project yet, so the text falls back to Poppins. Add the `.ttf` files under `Assets/fonts` to switch to the intended fonts.

## Styling

City Sim uses a fixed compact screen scale of `0.72` and has no text-percentage selector.
`PbCard.Size=Big` supports readable auction cards; `Compact=true` gives the hand a smaller
200px card face. `PbCard.ShowRarity=false` is used for contracts. `PbPanel.Fill=true` supports
constrained scrolling layouts, and `PbStat.Compact=true` keeps counters on one row with labelled
tooltips. `PbButton`, `PbCard` and `PbSlot` expose `CssClass` for semantic screen hooks.

- Tokens: `_tokens.scss` (mirrors the skill's `tokens.json`). Every component imports it with `@import "/Ui/Punchboard/_tokens.scss";`.
- Textures: `Assets/ui/punchboard/paper.png` (generated by the skill's `scripts/make_textures.py`).
- Each component's styles are in its `.razor.scss`, scoped by the component's tag name, e.g. `PbCard { ... }`.
- Do not style `Pb*` components from game code. If a screen needs something different, add a parameter or a class to the component.

## Viewing everything

`PbShowcase` is a `PanelComponent`. To look at it in play mode, add a GameObject with a `ScreenPanel` and a `PbShowcase` component (it can be removed again afterwards). It shows every component with working interactions: tap cards, toggles, tabs, "Open dialog".

## Animation hooks

Components that animate (`PbStat`, `PbSlot` pops, `PbHand` fan) do so inside `Tick()` with eased values from `Pb`. For bigger feedback (shake, sounds) use the game's `Feel/Feedback.cs`.

`PbHand` animates only live card faces. Retiring faces are deleted immediately before the fan
updates; changing their transforms while they are deleting can keep their CSS exit transition
alive and leave stale cards visible. Repeated empty/refill cycles must match the model count.

## Adding a component

1. Create `PbThing.razor` and `PbThing.razor.scss` in this folder, using the existing ones as a pattern.
2. Take all values from `_tokens.scss`. Add a token there first if something is missing.
3. Add it to `PbShowcase.razor` and check it in the engine.
4. Add a row to the table above and, if it is a new pattern, to the skill's `components.md`.
